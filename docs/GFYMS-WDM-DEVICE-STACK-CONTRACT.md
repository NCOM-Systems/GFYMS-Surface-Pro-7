# GFYMS WDM Device-Stack Manager Contract\n\n## Purpose\n\nThis document defines the first device-stack routing boundary above the typed\nWDM/IRP primitives. It models the ordered driver/device relationship that a\nWindows I/O request traverses without loading or executing Microsoft Windows\nkernel binaries.\n\n## Stack ordering\n\n`DeviceStack` stores entries from uppermost to lowermost:\n\n1. the newest attached filter/function driver;\n2. earlier attached drivers;\n3. the lowest driver at the end of the stack.\n\nAttaching a new entry inserts it at the uppermost position. Detaching removes\nonly the uppermost entry.\n\nEach entry owns an `Arc<DriverObject>` and an `Arc<DeviceObject>`. This keeps\ndriver lifetime and device-object lifetime explicit in the compatibility model.\n\n## IRP routing\n\n`DeviceStack::dispatch`:\n\n- rejects an empty stack;\n- rejects an IRP whose stack capacity is smaller than the number of attached\n  drivers;\n- aligns the IRP's current stack location with each driver before dispatch;\n- invokes drivers from uppermost to lowermost;\n- stops immediately when a driver completes the IRP;\n- stops on a non-success dispatch status;\n- preserves the final `IoStatusBlock`.\n\nThis is an explicit compatibility model rather than an assertion that Windows\ninternally implements every routing detail this way. A later kernel-backed\nimplementation can map these contracts onto native Linux mechanisms.\n\n## Completion boundary\n\nThe existing IRP completion primitive remains responsible for invoking\nregistered completion routines exactly once. The stack manager does not\nduplicate completion callbacks or synthesize completion after a driver has\nalready completed the request.\n\n## Scope boundaries\n\nThis milestone does not implement:\n\n- PE or `.sys` loading;\n- Windows kernel execution;\n- PnP state machines;\n- power-policy state machines;\n- DMA/MDL translation;\n- WDF/KMDF provider binding;\n- Windows object-manager namespace semantics.\n\nThose are separate compatibility boundaries and will consume the device-stack\ncontract as they are added.\n\n## Next boundary\n\nThe next WDM layer should add explicit PnP and power minor-function routing,\ndevice relations, and filter attachment metadata before any Surface-specific\ndriver experiment is connected to the model.\n
